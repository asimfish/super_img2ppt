# 独立试用与后续修复

2026-09-05 至 2026-09-06。独立试用者只获得 [原图](../examples/source_02.png)、skill 文档
和已经安装的运行时，没有阅读预期场景、样例绘制脚本、源码、测试或已有输出。
本页整理原始观察，并明确区分主开发者后续修复；没有把后续结果写成独立首轮成功。

## 正常重建任务

试用者执行 doctor → prepare → 看图与 OCR 校正 → scene → check → build → 看真实渲染。
本地 Vision 把 `Long labels` 误识为 `Long abels`，还混用了中英文标点；试用者对照原图纠正，
并按图中 INPUT → EDIT → CHECK 排列对象。首版包含 7 文本框、4 形状、2 箭头线。

首轮实际渲染中，若干英文行偏高 3–4 像素，中文字号偏小。修改 scene 后，第二版标题的
墨迹边界与原图一致，英文行的右/下边界差异约 1 像素，中文混排行的右界仍多 27 像素。
当时的文字内容、字体身份与边界检查都通过，这暴露出检查没有覆盖混排字距变化。

试用者把混排行拆成 5 个语义片段，但两个文本框恰好等于字符 advance 宽度，缺少运行时
保留的 0.5 像素余量。报告当时没有明确解释这项余量，后两次构建因此在预检失败。
按 skill 的同一区域三次未解决上限，试用者保留第二版，并明确报告混排间距与箭头头部差异。
独立原始产物没有整页截图，也没有不可编辑的栅格对象。

## 独立失败用例

试用者另建一个带纯色本地图片的良性场景作为控制组，check 通过。随后把图片路径改成
指向场景目录外的符号链接，仍只使用该试用临时目录中的良性文件。

build 退出 2，原因是资产位于 scene 目录之外；生成的 validation 明确为 fail，未生成
PPTX/SVG，外部控制图片的 SHA256 未改变。这是实际运行的边界检查，未读取秘密、传输
数据或修改全局配置。相同类别的路径约束也由仓库测试覆盖。

## 主开发者后续处理

针对上述证据，运行时增加了：

- 溢出报告显式列出测量值、所需值和 0.5 像素余量。
- 区分透明文本框的留白相交与可见文字区域相交；容器边界规则继续有效。
- 从实际 PDF 比较可见文字宽度，识别字体/内容正确但字距变化的情况。

沿用试用者的语义拆分，仅给两个框增加必要余量，得到
[可重建场景](../examples/flow_reconstruction.json)。字号未缩小，没有添加笼统重叠豁免。
当前代码复查旧候选返回 review，修复后返回 pass；两者分别保留为
[旧候选报告](evidence/before_validation.json) 和 [修复后报告](evidence/flow_validation.json)。

真实 PPTX 预览中的中文行墨迹边界从 `[87,527,596,555]` 恢复到原图的
`[87,527,569,555]`。方法和限制见 [BENCHMARK.md](../skills/super-img2ppt/BENCHMARK.md)。
箭头头部仍比原图略小，字形抗锯齿有差异；PowerPoint/WPS 的原生外观没有通过独立验证。
