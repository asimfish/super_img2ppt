# compare-roi 独立实测结论

**本次未发现数值正确性缺陷。** 三处既有冻结 ROI 的工具结果与独立 Pillow/Python 集合计算完全一致；错误分辨率输入正确返回 fail（退出码 2）。原始场景、原图和 build_04 均未修改，没有安装依赖或改仓库。

输入为 Cosmos Policy 完整 Figure 2 原图及最终 PPTX 经 LibreOffice→PDFium 得到的实际渲染，两者均为 1195×476。沿用原测量区域和黑墨迹条件 `max(R,G,B)<150`，在新 CLI 中等价表达为 `--color '#000000' --tolerance 149`，未根据结果调整阈值或区域，也未对齐／缩放输入。

| 隔离区域（x,y,w,h） | 源／实际像素数 | 边界差 L,T,R,B（px） | IoU |
|---|---:|---|---:|
| conditioning 标题 (160,0,295,33) | 1686 / 1593 | 0,0,-1,1 | 0.347165 |
| current wrist img 小标签 (198,42,104,19) | 241 / 243 | -1,0,0,0 | 0.386819 |
| V(s′) 公式 (1095,439,65,31) | 273 / 233 | 1,0,-1,0 | 0.228155 |

三处均未触碰 ROI 边界；背景没有混入黑色掩膜。`audit.py` 独立验证源／实际计数、绝对右下开区间边界以及交并集；intersection/union 分别为 845/2434、135/349、94/412。对应结果记录在 `independent_audit.json`。已查看放大的源／实际裁剪及二值墨迹诊断图 `audit_contact.png`，并查看工具原生公式 `comparison.png`；工具保存掩膜以白色标示选中墨迹，其白色像素数也逐项匹配报告；独立 contact 图为便于阅读使用相反显示色。

数字与可见差异相符：标题的总长度接近，但多个字母内部笔画和相对间距不同；小字号标签仅移动或改变一个像素就会显著影响 IoU；公式外框近乎相同，但 V、s、prime 和括号的笔形／内部位置仍不同。工具始终返回 review，不把这些边界近似误报为字体一致或保真通过，是合理行为。

不适用输入使用同一个真实 PPTX 的默认 1600×638 预览，直接与 1195×476 原图比较。`wrong_resolution/region.json` 正确保存两张输入 SHA256 和尺寸不匹配错误，没有偷偷 resize，命令返回 2。该失败报告只提供“不匹配”的文字，没有同时记录两组实际尺寸；可考虑补充 expected/actual size 方便诊断，但不是数值正确性问题。

局限：IoU 对字号、抗锯齿、阈值和一像素偏移非常敏感，不能将 0.228 理解为“公式只有 22.8% 正确”，也不能从这些数值区分字体替代和字符间距原因。工具无法确认输入图片来源；本次通过已有 build_04 的实际 PDF 与源宽度渲染记录建立来源链。三处文字/公式诊断不能代表整图精度或遗漏检查。

复现命令见 `commands.sh`，每次需要全新输出目录；完整 CLI 输出见 `commands.log`。每个子目录都保存 `region.json`、裁剪、掩膜和对比图；无效输入也保留失败证据。
